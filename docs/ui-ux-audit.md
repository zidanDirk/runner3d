# Task13 改造前 UI/UX 审计

已读取当前入口、HUD、Progression、MobileSettings、ProfileController、动画控制器、加载/输入/页面生命周期、移动适配与71视觉基线。基准代码/哈希/原图保存在 `artifacts/ui-ux/before-source`、`before-hashes.json`、`before`、`before-ui`。五张真实桌面/手机原图没有页面异常。

现有优点：实际AABB与固定步稳定；原生dialog、44px触摸、Reduced Motion、独立设置存储可复用；商店从配置描述效果，真实控制器拥有购买、领取和死亡结算。Task13不重写这些业务。

| 发现 | 对应改造 |
| --- | --- |
| 入口直接加载城市并叠准备菜单，缺少正式首页 | 轻量首页只加载City Runner；游戏Canvas按需挂载，与首页预览互斥 |
| 无新手引导完成/跳过状态、无外观入口 | 非阻塞首次提示、三步可重看引导；三免费服装材质变体共享GLB |
| 商店/任务在准备/暂停/结束菜单内部各自开窗 | 单层互斥导航，统一入口和返回，复用现有数据及交易 |
| 设置有侧栏音频/动态效果和两个按钮等重复入口 | 一个统一设置内容，首页/暂停可达，HUD入口复用导航 |
| 暂停缺少明确返回首页与退出规则 | 确认放弃本局；只保留已发生生涯事实，不支付钱包，不伪造死亡 |
| 结束只强调得分和最佳，距离/钱包/任务/新纪录不完整 | 开局快照+真实lastSettlement只读摘要，区分收集与钱包入账 |
| 页面返回依赖局部组件状态，没有统一屏幕模型 | 纯TS导航reducer；物理状态继续由GameStore独占 |
| 缺少首次进入到第二局与刷新恢复的产品旅程测试 | 实际收集/死亡/购买/任务/重玩/刷新；不篡改余额冒充验证 |

设计决策：沿用暖橙、城市跑道几何、深蓝菜单与原有字形/图标。统一token和按钮/面板；核心操作突出，状态用文字/图标而非仅颜色。游戏画布布局和镜头先保留，HUD靠边。UI路由不引入框架，不为首页加载城市，不复制GLB。

验证计划：每阶段unit/strict，完成后旧+新增浏览器、71基线对比并审查有意差异后逐项更新、20种产品画面、真实新玩家/中途退出/异常流程、生产/加载/15资源/build。性能实测首页交互与字节、唯一Canvas/GLB请求、入局和商店耗时、多次真实旅程后的Renderer/Mixer/Audio/监听/heap与正式运行帧间隔；不将桌面模拟手机称为真机。

# 累计任务

Task12保持九个ID/目标/奖励不变。真实ProfileController生涯模拟记录每项首次完成领取局、奖励占比和重复领取保护；不把新目标重新覆盖旧档，不需要schema迁移。样本规模、策略和完成成本见[balance-simulation.md](balance-simulation.md)及最终平衡报告。

`src/progression/config.ts` 定义九个稳定ID，`getMissionViews`派生可读状态。无日期、每日重置、登录或网络依赖。

| 链 | 累计目标（阶段1 / 2 / 3） | 金币奖励 |
| --- | --- | --- |
| coins | 100 / 300 / 800枚 | 40 / 80 / 150 |
| distance | 1000 / 3000 / 10000米 | 40 / 80 / 150 |
| powerups | 5 / 15 / 40次拾取 | 40 / 80 / 150 |

统计来自每个真实固定步的权威coins、floor(distance)、powerupsCollected差值，以runId和tick水位去重。只在对应整数指标发生增量时检查预索引的该类任务链，不每渲染帧扫描全部任务；UI约20Hz读取稳定快照。距离存档按整米，局内每步取累计floor差值，避免浮点累加误差。

目标是**生涯累计**，领取和切阶段不扣减统计。例如累计320金币时，先领取coins-1，再解锁已达标的coins-2；不是在领取后再收集300枚。前阶段必须领取才解锁下阶段。完成事件只通知一次，奖励必须通过claim(ID)原子事务发放；任务页重绘、打开、刷新不会自动给钱。已领取ID最多九项，验证时拒绝未知/重复ID、跳阶段或不足目标的非法状态。

暂停冻结游戏进度，任务可在准备、暂停或结算菜单查看/领取，关闭后保持暂停。重试保留统计与已领取状态；放弃局的已发生统计保留，当局钱包结算仍按经济文档处理。开发定位整局不参与生涯统计。没有真实日期、离线补进度或无限奖励。

```sh
npm test -- tests/unit/progression.test.ts
npm run test:progression
npm run balance:simulate
```

扩展目标时维持稳定ID和明确schema迁移；更改目标不能使已领取记录在同schema下突然非法。新增任务类别需给权威增量事实、配置校验、去重与存储兼容测试，不能从动画或UI按钮意图推断完成。

# 金币钱包与升级商店

Task12保留价格、钱包和schema1；新版模拟通过`npm run balance:analyze`与`balance:report`评估四种购买顺序、每级边际效用和删失偏差。旧Task11的18%错道模拟仍可从历史测试复现，与新beginner/casual/expert策略不能直接当作同样本比较。新增结果及限制见[game-balance.md](game-balance.md)。

初始钱包0金币。Run Coins为当局真实金币枚数，Wallet Coins为可消费余额；双倍得分只影响分数。纯TS `ProfileController` 执行同步原子事务，渲染和音效无权写钱包。

正常死亡时以runId/tick水位将本局金币结算一次；重复Game Over、重复发布、重新开始不能重复结算。暂停/返回设置不结算。中途重新开始、换seed或关页视为放弃，当局金币不进入钱包；已产生的生涯金币/距离/拾取统计保留，并在暂停、重试、隐藏/离开页时保存。没有续局恢复或离线计时补偿。

金额和统计严格限制为非负安全整数；溢出按MAX_SAFE_INTEGER饱和，奖励/结算记录实际加入金额。无负余额、NaN或Infinity。存储失败仅影响持久化，内存内事务和去重继续有效，界面提示本页临时进度。

三个项目均Lv0→3，价格100/250/500金币。商店展示当前等级、当前/下级效果、价格、余额与禁用原因；满级或金币不足不可购买。购买提交expectedLevel，旧点击即使重复送达也不能再次扣款；同一次面板打开还锁住已成功升级的项目，避免双击连购两级。关闭重开可继续购买下一等级。升级永久保留，下一局读取；当前局的道具规则不改变。

任务奖励40/80/150金币，每类三阶段，必须主动领取，每ID仅一次。领取不增加生涯金币或得分，不能通过奖励触发金币任务再循环奖励。全部九任务奖励总上限810金币。钱包不用于真实货币、付费或等待机制。

配置在 `src/progression/balance.ts` 汇总，改动 `game/balance.ts` 或 `progression/config.ts` 后运行：

```sh
npm run balance:simulate
npm test
npm run test:progression
```

模拟实测写 `artifacts/progression/balance.json`：100个独立seed的“每行18%选错跑道”新手策略，另40个配对seed用6%错误率比较无道具/单类/组合/满级。它们驱动真实120Hz引擎，最终真实碰撞结束；不是人类平均水平。报告平均收入、距离、分数、护盾抵挡、第一笔升级可支付局数，逐局明细也保留。相同策略不是相同生存距离：护盾预期延长奔跑，报告应同时列出距离，不能把额外收益全归因于加分。

重复同seed正式完成新局继续获得金币是离线单机的正常玩法；反复放弃不能结算当局钱包，但能推进有限任务链。测试覆盖重复结算、重复领取、旧购买请求、上限饱和和放弃规则。localStorage可由用户修改，不能宣称防作弊或服务端可信。多标签页没有跨页经济锁，建议只在一个游戏页游玩同一存档。

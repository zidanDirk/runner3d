# Runner3D · 最小可运行版本设计

本文记录第一阶段设计。第二阶段保持以下游戏规则不变，仅将低栏外观替换为本地 Blender 自动生成的 GLB；新增流程见 [asset-pipeline.md](asset-pipeline.md)。

## 需求与范围

三条固定跑道、自动前进、A/D/左右键换道、Space 跳跃、S/下键滑铲。障碍分为低栏（可跳）、高架（可滑）、箱墙（换道）。金币增加得分；跑过距离也增加得分。碰撞结束，支持同 seed 重试和更换 seed。附加 Escape 暂停、失焦暂停和屏幕按钮，便于浏览器使用。

采用 TypeScript strict、React、Vite、Three.js、React Three Fiber、Drei、Vitest、Playwright。初期只用 box、capsule、cylinder 等基础形状，做清晰的速度和障碍提示；不做正式美术、复杂动画、粒子、音效或后端。

## 目录与依赖方向

```text
src/
  game/       config / types / random / level / collision / engine
  runtime/    clock / store / keyboard
  scene/      GameScene / World / Runner / Obstacles
  ui/         GameUI / icons
  App.tsx     组合场景与交互
tests/
  unit/       引擎、时间步和可通行性
  e2e/        键盘、完整循环、截图与画布检查
```

`game ← runtime ← scene/ui ← App`。游戏域没有浏览器或图形依赖。运行时唯一拥有模拟，RAF 驱动累加器；R3F 仅做视觉同步。UI 通过订阅读取每秒最多 20 次快照，场景直接读只读实时状态，避免每帧 React 全树更新。

## 玩法简报

玩家扮演几何体跑者，在悬浮的三轨道路上不断前进。主操作是预判并换道，辅操作是跳跃与滑铲。每隔数秒读取下一个障碍行，选择空跑道或冒险跨越障碍收集金币；速度随距离从 16 m/s 提升到 24 m/s。熟练玩家提前识别轮廓、平滑换道、把握跳跃/滑铲时机。

核心循环：玩家通过换道、跳跃和滑铲延长奔跑距离，逐步加速带来压力；金币与距离增加分数，碰撞显示成绩并立即允许同路线重试。

## 路段计划与公平性

- 玩家固定在世界 z=0，世界按照模拟距离移动；道路以分块循环，实体按可见距离生成与回收。
- 开局 48m 为无障碍准备区，中央金币引导前进；前方约 140m 可见，雾线弱化远端。
- 每个障碍行间隔 26m。每五行有一行恢复区，其余最多两条道放置障碍，始终保留空道。
- 生成器保留上一安全跑道，下一安全道只能相同或邻道。最高速行间时间 26/24 ≈ 1.08 秒；换道耗时 0.18 秒，加上实体深度与碰撞区后仍有余量。
- 跳跃约 1 秒，滑铲 0.75 秒；碰撞使用玩家实际 x/y 与障碍 AABB，在固定 tick 执行。无需真实刚体，使用自定义碰撞最符合跑道规则。
- 规则保证存在连续的纯换道解，不要求玩家必须跳跃/滑铲才有解。金币不参与安全性约束。

## 时间与可复现性

以 120Hz 固定步模拟。单帧最多接收 0.1 秒，避免标签切回时突进；失焦暂停，恢复后重置累加器。输入在下一 tick 消费。PRNG 使用 seed 字符串哈希与整数状态，关卡不读取时间。重试保留 seed，完整重置世界与输入。

得分 = `floor(distance) + coins × 25`。最高分只存本地，存储不可用则回退到当前会话。固定 seed 可复现关卡与同 tick 输入序列，不承诺不同设备的人类按键时间完全一致。

## 视觉与验收

浅色工作台配深蓝夜色跑道，橙色跑者/重点按钮、金色金币、珊瑚色低栏、青绿色高架，箱墙采用深灰与警示条。俯后方相机让玩家、三轨和连续障碍可见。菜单、奔跑、暂停、结束都有明确状态；HUD 在画面边缘。

验收覆盖纯逻辑测试、多 seed 长距离可解性、实体数量上限、真实输入的失败/重试闭环、WebGL 非空画布、桌面和窄屏截图、生产构建与预览。
